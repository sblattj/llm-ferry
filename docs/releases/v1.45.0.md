# llm-ferry v1.45.0 — choose where a new tmux session starts

`ferry tmux --dir PATH` starts a new session on the client in `PATH` instead of the home directory.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Added

- **`ferry tmux --dir PATH` (host).** Passes `-c PATH` to `tmux new-session`. `PATH` is a path on the client. A leading `~` or `~/` means the client user's home, and the client's shell expands it as `"$HOME"`. Every other value is single-quoted, so the client's shell can't run it as a command.

## Notes

- `--dir` only affects a new session. When the session already exists, `-A` attaches to it and tmux ignores `-c`, so its windows keep their own directories.
- An empty value, a value containing a newline, carriage return or NUL, and `~otheruser/...` are refused with an error.
- Without `--dir`, the ssh command is exactly the same as in v1.44.

## Tests

- `lib/ferry-tmux.test.py` (`TmuxDirTest`): a path with a space, `~` and `~/code/foo`, a hostile `;touch` value, and the refused values. The quoting is also checked in a real `sh`: `~/code/foo` expands to `$HOME/code/foo`, and the hostile value comes through as literal text without creating its file.
