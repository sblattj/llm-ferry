# llm-ferry v1.38.0 — safe help, clean pipes, named offers

A hygiene release: nothing new to learn, several sharp edges removed.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## What's new

- **`--help` never runs a command.** `ferry reload --help` used to reload the
  live front door, because `reload`, `install`, `status`, `share` and `log`
  ignored their arguments. Now `-h`/`--help` on any subcommand prints that
  command's help and exits 0, `ferry help <cmd>` works, and the arg-less
  commands reject stray arguments with exit 2. `dash` still forwards `--help`
  to its child scripts, which answer it themselves.
- **Colour only on a terminal.** Every colour-emitting line in `lib/` now goes
  through one helper that colours only when the stream is a tty and honours
  `NO_COLOR`. Piping `ferry expose --token` or `ferry status` yields plain
  text you can scrape.
- **`ferry offer --as NAME`.** Choose the name clients request; offering a
  name that already points elsewhere fails unless `--replace` is given, and
  each offer prints its `GET /file/<name>` URL.
- **`.app` bundles keep their signatures.** Offered folders still follow
  symlinks, except inside a `*.app` bundle, so a copied app passes
  `codesign --verify --deep --strict`. `--deref` / `--no-deref` override per
  offer; old manifest entries keep working. `ferry offer --selftest` exercises
  all three payload shapes.
- **Releases are automatic.** Pushing a `v*` tag now creates its GitHub
  Release (`.github/workflows/release.yml`, notes from the tag message or
  `docs/releases/<tag>.md`). The 11 releases missing since v1.29.4 were
  backfilled.

## Notes

- A running share server keeps the old offer code until it is restarted.
- `ferry msg hello --help` now prints help rather than sending the message.
