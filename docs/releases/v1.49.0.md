# llm-ferry v1.49.0 — goal plugin 1.3.0: goals run in parallel across opencode processes

ferry now installs version 1.3.0 of the OpenCode goal plugin (`opencode-goal-pro-max-complete-plugin`). In 1.3.0, a second opencode process no longer gets stuck with "Goal plugin is locked by another opencode process". Separate processes run their goals at the same time, and a session another process has left idle is handed over within a few seconds.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Changed

- **Goal plugin pinned to `v1.3.0`** (was `v1.2.0`). A process now holds a session's lease only while it is driving that session: an active goal, a `/goal` turn, a continuation, or a prompt. After 3 s idle it releases the lease (plugin option `idleLeaseReleaseMs`). Leases heartbeat, so a crashed or frozen owner's lease is reclaimed after about 2 minutes. An owner that loses its lease stops writing. A session with a running goal still belongs to one process; fork with `opencode --continue --fork` to run two goals from one conversation. Plugin release notes: [v1.3.0](https://github.com/sblattj/opencode-goal-pro-max-complete-plugin/releases/tag/v1.3.0).
- The pinned spec changes, so OpenCode installs the new version fresh. The old 1.2.0 entry is still recognized by package name and replaced.
- The bundled `using-the-goal-plugin` skill is unchanged: the plugin's `v1.3.0` copy is byte-identical to the one ferry already ships. Only its provenance comments now name `v1.3.0`.

## Tests

- `lib/ferry-integrate.test.py` and `lib/ferry-clientbootstrap.test.py` now expect the `v1.3.0` spec and version.
