# llm-ferry v1.49.4 — an idle `ferry tmux` session no longer drops

A tunnel published with `ferry expose` / `ferry expose-tmux` stays up while idle, instead of closing after about 10 seconds of quiet.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Fixed

- **An idle tunnel no longer closes itself.** `ferry expose` opened its local-service connection with a 5 s timeout and its relay data connection with a 10 s timeout, and never cleared them. The first read that waited longer raised, the splice ended, and an idle `ferry tmux` session died with `Connection closed by remote host` while both machines were fine. Both timeouts are now cleared once the connections are open, as the relay half already did. **Update the client with `ferry update`, then restart its `ferry expose-tmux` (or `ferry expose`)**: the running process keeps the old code.
- **Idle flows are kept alive through firewalls.** TCP keepalive is now set on the tunnel's data channels at both ends and on the client's control connection, and `ferry tmux` runs ssh with `ServerAliveInterval=30` and `ServerAliveCountMax=4`. A firewall or VPN agent that drops quiet connections (such as Zscaler's client connector) sees traffic, and a session whose client really is gone ends within about two minutes instead of hanging.

## Tests

- `lib/ferry-relay.test.py`: a new test sends through the tunnel, stays silent for 12 s, and sends again; it fails on v1.49.3 and passes now.
- `lib/ferry-tmux.test.py`: the exact-argv tests include the two `ServerAlive` options.
