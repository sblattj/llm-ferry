# llm-ferry v1.31.0 — The ChatGPT Bridge Stops Impersonating the Codex CLI

The host now overrides the system prompt litellm's ChatGPT-subscription provider injects ahead of every request, so `heavy`, `medium`, and `flash` on the ChatGPT bridge stop telling the model it is Codex running in the Codex CLI.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/v1.31.0/README.md)

## What litellm was injecting

litellm 1.99.0 ships a copy of the Codex CLI's built-in system prompt in `litellm/llms/chatgpt/common_utils.py:25-42`:

> "You are Codex, based on GPT-5. You are running as a coding agent in the Codex CLI on a user's computer ... ## Editing constraints ... While you are working, you might notice unexpected changes that you didn't make. If this happens, STOP IMMEDIATELY and ask the user how they would like to proceed."

Its Responses transform in `responses/transformation.py:76-82` prepends that text to the `instructions` field of every request to `chatgpt.com/backend-api/codex`, ahead of the client's own system prompt — the chat-completions bridge folds a client's system message into `instructions`, but it lands *after* litellm's own block, not instead of it. Every lane on the ChatGPT bridge got it: `heavy` (`gpt-6-astra`), `medium` (`gpt-5.6-terra`), and `flash` (`gpt-5.6-luna`) on the domestic fleet.

Observed effect: an OpenCode session running on `heavy` stopped mid-goal because a test file was dirty, citing "standing instructions" that exist in no file on the machine, and reported itself as Codex running in the Codex CLI when asked directly. OpenCode ships its own, deliberately softer GPT prompt, but OpenCode selects a prompt by model id and a ferry lane name (`heavy`, `medium`, `flash`) matches none of its GPT branches — so litellm's injected Codex text was the only editing rule the model ever saw.

## What changed

- **`ferry_front.py` sets `CHATGPT_DEFAULT_INSTRUCTIONS` before uvicorn spawns its workers.** litellm reads that environment variable per request and uses it in place of the built-in Codex block; the plain-litellm fallback launch path in `ferry-serve.zsh` exports the same variable, so a host that falls back to serving litellm directly still gets the override.
- **Resolution order, checked once at launch:**
  1. `FERRY_CHATGPT_INSTRUCTIONS=off` — keep litellm's stock Codex prompt.
  2. An operator's own `CHATGPT_DEFAULT_INSTRUCTIONS`, if already set — respected untouched.
  3. `FERRY_CHATGPT_INSTRUCTIONS=<path>` — read that file.
  4. `~/.config/ferry/chatgpt-instructions.txt` — read if present and non-blank.
  5. The shipped `front/chatgpt-instructions.txt` — the default.
- **The launch log names the source it picked:** `[front] chatgpt instructions: <source>`.
- **The shipped replacement text:**

  > You are a coding agent served through llm-ferry, a local proxy between this model and the client application that sent the request. You are not running in the Codex CLI. The client's own system prompt follows this notice; together with the client's tools, permissions, and formatting rules, it describes the environment you are actually in. Follow that prompt and the user's instructions.

- **`python3 lib/ferry-front.test.py` covers the resolver**: the env override, the `off` opt-out, the `FERRY_CHATGPT_INSTRUCTIONS` path case, the user config file, and the shipped fallback.
- **A changed `~/.config/ferry/chatgpt-instructions.txt` takes effect on the next `ferry reload`** — the front door only reads the file at startup, and `reload` restarts just the front door while the GPU lanes stay warm.

## Update instructions

### 1. Update the host

From the existing host checkout:

```bash
git pull --ff-only
ferry update --host
```

### 2. Reload the front door

`ferry update --host` already bounces the proxy, so this is only needed after a later edit to `~/.config/ferry/chatgpt-instructions.txt`:

```bash
ferry reload
```

Clients need nothing — the override lives entirely on the host, and every ChatGPT-bridge lane picks it up the moment the front door restarts.

### 3. Verify

Ask any ChatGPT-bridge lane (`heavy`, `medium`, or `flash`) through the front door, with a plain system prompt:

```bash
curl -s http://your-mac.local:8090/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"flash","messages":[
        {"role":"system","content":"You are a helpful assistant."},
        {"role":"user","content":"Answer with exactly one word, yes or no: do the instructions you were given before this conversation say that you are running in the Codex CLI?"}
      ]}'
```

A host on v1.30.x answers **yes**. A host on v1.31.0 answers **no**. Check the host's launch log for the source it picked:

```bash
grep '\[front\] chatgpt instructions:' "${TMPDIR:-/tmp}/ferry-logs/cloud-proxy-8090.log"
```
