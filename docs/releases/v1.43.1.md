# llm-ferry v1.43.1 — the goal plugin points at opencode-goal-pro-max-complete-plugin

The goal plugin's repo was renamed to `sblattj/opencode-goal-pro-max-complete-plugin`, and the URL ferry pinned (`sblattj/OpenCode-goal-plugin` v0.11.0) now returns 404. Every `ferry opencode` (and every `ferry update` that re-wires opencode) kept writing that dead spec, so opencode failed to install the plugin on each start. This release pins the renamed plugin at **v1.1.0**, and it stops adding a remote spec next to a local install of that plugin.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Fixed

- **New pin.** `opencode.json` now gets `opencode-goal-pro-max-complete-plugin@https://github.com/sblattj/opencode-goal-pro-max-complete-plugin/archive/refs/tags/v1.1.0.tar.gz`. Every older spelling, including the dead v0.11.0 spec, is rewritten to it, and the old cache directory is purged even when no config names it any more.
- **A local install wins.** If a `plugin` array already holds a local path or `file://` URL to the goal plugin, such as the pro-max installer's `file://…/.local/share/opencode-goal-pro-max-complete-plugin`, ferry writes no remote spec into that file and removes any that is there. In `tui.json` it also drops its own managed-copy entry, so opencode loads the plugin once, not twice. The run prints `Plugin: provided by <that entry>`.
- **The skill follows the plugin.** `using-the-goal-plugin` is now a verbatim copy of v1.1.0's skill, which adds the todo-mirror guidance. A local install of the pinned package itself still gets the skill. A fork under any other package name does not.
- **`client-cleanup.sh`** recognises the new package and repo names as well as the old ones.

## Notes

- On a host that already ran v1.43.0: run `ferry update` (or `ferry opencode`). The dead spec in `opencode.json` is replaced with the new pin, or removed outright when a local install of the plugin is already there, in which case ferry's managed-copy entry also leaves `tui.json`. The old managed copy under `~/.local/share/ferry/opencode-goal-plugin` stays on disk but nothing points at it.
- Verified live on opencode 1.18.34. With a fresh HOME, ferry pre-installs 1.1.0 and refreshes its managed TUI copy from it. With a copy of a real config that had the pro-max install plus the dead spec, ferry leaves exactly one entry in each file and installs the v1.1.0 skill.
