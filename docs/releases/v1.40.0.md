# llm-ferry v1.40.0 — Cline (VS Code) support

ferry now wires **Cline, the VS Code AI extension**, the same way it wires opencode and Claude Code: one `ferry cline` command (or a plain client bootstrap) points Cline's OpenAI-Compatible provider at the ferry endpoint by lane name — snapshotting, merging, and documenting every file it touches.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## What's new

```bash
ferry cline                                        # wire Cline at the default host/port, `heavy` lane
ferry cline --host your-mac.local --port 8090      # explicit host
ferry cline --model flash --key "$LITELLM_MASTER_KEY"
```

- `ferry cline` writes Cline's three config files (`globalState.json`, `secrets.json`, `providers.json`) under `~/.cline`, merging around every key it did not write, with `<file>.<UTC>.ferry.bak` snapshots first (pruned to the last 10). The bootstrap wires Cline by default (`--no-cline` narrows it, recorded as `cline_mode` in `client.json`), and `client-reset.sh`, `client-cleanup.sh`, `host-reset.sh`, and `client-to-host.sh` all know the scope: re-apply on reset, restore-or-strip on cleanup (never touching chat history), re-key on client-to-host.
- The model picker's lane list comes straight from the host: Cline's OpenAI-Compatible picker calls `GET /v1/models`, which ferry already serves, so ferry lanes appear automatically. The default lane is `heavy`; if the chosen lane isn't served, `ferry cline` falls back (warning printed) rather than wiring a dead lane.
- **Per-device keys flow through** (building on v1.39.0): `ferry cline` resolves the client profile's `api_key` (the enrolled device key) before `master_key`, so a bootstrapped client's Cline carries its own revocable device key — and `~/.config/ferry/cline.json` records it as `api_key`, never mislabeled as the master.

## How it works

- `lib/ferry-cline.zsh` — the `ferry cline` command, mirroring `ferry claude`'s host/port/key resolution and snapshot discipline. It writes all three of Cline's file-backed stores while VS Code is closed, records `~/.config/ferry/cline.json` for reset/cleanup, and treats a missing VS Code or Cline install as a note (pre-seeding a machine before its first launch is a supported flow), not an error.
- File-backed config, not VS Code settings: Cline stores provider state in plain JSON under `~/.cline/data/` — extension state in `globalState.json` (the `openai` provider id, base URL, model ids, custom `openAiHeaders`), the API key in mode-0600 `secrets.json`, and the SDK-shared mirror in `settings/providers.json` (the `openai-compatible` provider id). The two different provider ids for the same setting are Cline's own duality; ferry writes both. [The internals →](../deep-dives.md#the-cline-takeover-internals)
- `client-bootstrap.sh` grows a `--no-cline` scope flag alongside the opencode/claude ones (no CLI detection — pre-seeding without VS Code installed is the norm), persists `cline_mode`, and runs the takeover after the claude step. On a v1.39.0+ host the enroll step has already minted the device key by then, so the takeover bakes it in.

## Notes

- **VS Code must be closed when wiring** — the extension caches config in memory and can overwrite the files from memory. `ferry cline` warns and continues when it detects a running VS Code.
- **Fresh-install trap closed**: Cline defaults `actModeApiProvider` to `openrouter` when absent, so writing only the `providers.json` mirror is silently ignored. Ferry always writes `globalState.json`, and always writes a non-empty API key (Cline only sends `Authorization` when a key exists).
- **Fleet header baked at install time**: unlike opencode's `{env:FERRY_FLEET}` live placeholder, a static JSON file can't resolve environment at runtime — `ferry cline` bakes `X-Ferry-Fleet` in only when `$FERRY_FLEET` is set at the moment it runs. Re-run `ferry cline` to re-bake.

## Tests

New `lib/ferry-cline.test.py` (stub `/v1/models` server, throwaway `HOME`): the three files' exact shapes, secrets mode 0600, unknown-key merge survival, snapshot creation, lane fallback when the chosen model isn't served, offline-write-with-warning, `--key` precedence, plus static contract checks (build MODULES entry, dispatch case, usage row). `lib/ferry-clientbootstrap.test.py` extends to the new scope: `cline_mode` defaults to `full`, `--no-cline` records `none` and skips the takeover, and a full bootstrap writes the ferry provider into `~/.cline/data/globalState.json`.
