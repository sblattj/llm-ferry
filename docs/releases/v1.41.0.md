# llm-ferry v1.41.0 — Codex CLI and Prime Agent support

ferry now wires **the OpenAI Codex CLI** and **Prime Agent** the same way it wires opencode, Claude Code and Cline: one `ferry codex` / `ferry prime` command (or a plain client bootstrap) points each tool at the ferry endpoint by lane name, without touching anything the tool owns.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## What's new

```bash
ferry codex                                        # install codex-ferry / codex-ferry-flash
ferry codex --host your-mac.local --port 8090 --key "$LITELLM_MASTER_KEY"
ferry prime                                        # add the 'ferry' provider to Prime Agent's models.json
prime-agent --provider ferry --model heavy
```

- **`ferry codex`** installs `codex-ferry` (lane `heavy`) and `codex-ferry-flash` (`flash`) in `~/.zshrc`. They launch Codex with `-c` overrides — `~/.codex`, `CODEX_HOME` and bare `codex` are never touched, and the key travels in an env var, not argv. Codex's `/goal` works through the wrappers. Codex validates `spawn_agent` model names client-side against its model catalog, so `ferry codex` also writes `~/.config/ferry/codex-catalog.json` (tiers `heavy`, `medium`, `light`, `super-light`, copied from your newest listed models in `models_cache.json`, with a minimal fallback) and each wrapper passes `model_catalog_json` plus a `developer_instructions` override telling Codex to pass those tier names, never an OpenAI id, as the subagent model; the wrappers run at high reasoning effort, parent and subagents. Codex 0.158+ only speaks `wire_api="responses"`, so the lane must serve `/v1/responses` (the ferry front door does).
- **`ferry prime`** adds one `ferry` provider (OpenAI-compatible, every served lane as a model) to Prime Agent's `models.json` with a text-surgical edit: comments, trailing commas and other providers survive byte for byte, snapshots come first (`models.json.<UTC>.ferry.bak`), and a file it cannot edit safely is left untouched with the snippet printed.
- **Both are first-class clients**: `client-bootstrap.sh` grows `--no-codex` / `--no-prime` (default on, no CLI detection — both pre-seed before the tool exists, with install hints `npm i -g @openai/codex` and the Prime Agent installer one-liner), records `codex_mode` / `prime_mode` in `client.json`, and `client-reset.sh` re-applies exactly the recorded scope (absent key means none; failures are warnings). `client-cleanup.sh` unwires surgically — it strips the `ferry codex profiles` block from `~/.zshrc`, and restores the newest `.ferry.bak` (else strips only `providers.ferry`, ownership-guarded) in `models.json`; `~/.codex` and `~/.prime` are never deleted. `host-reset.sh` re-applies both at `127.0.0.1` (`ferry codex --wrappers`, `ferry prime`) and `client-to-host.sh` re-keys them with the front-door key.
- Per-device keys (v1.39.0) flow through: both resolve the client profile's `api_key` before `master_key`, and their records never mislabel a device key as the master.

## How it works

- `lib/ferry-codex.zsh` — the `ferry codex` command: a marker block of shell functions with baked host/port/key and a `~/.config/ferry/codex.json` record. [Internals →](../deep-dives.md#codex-wiring)
- `lib/ferry-prime.zsh` — the `ferry prime` command: JSONC-aware text surgery on `models.json` verified against the prime-agent source (wrapped `{"providers": {...}}`, `baseUrl` is the `/v1` root, `compat` pinned to the plain dialect). [Internals →](../deep-dives.md#prime-agent-wiring)

## Notes

- **Prime Agent has not been tested end to end** against a live `prime-agent` binary: the file shape and URL join come from its source, and whether a running daemon re-reads `models.json` without a restart is unknown. Codex was exercised against a real 0.158 binary in the `ferry codex` suite.
- Prime Agent is very new and fast-moving (beta channel); re-run `ferry prime` if its config format shifts.
- Codex prints a non-fatal "Model metadata not found" warning for ferry lane names; the request is still sent.

## Tests

New `lib/ferry-codex.test.py` and `lib/ferry-prime.test.py`. `lib/ferry-clientbootstrap.test.py` extends to the new scopes: `codex_mode` / `prime_mode` default to `full`, `--no-codex` / `--no-prime` record `none` and touch nothing, reset re-applies and skips per the recorded scope, failing steps warn instead of aborting, and cleanup strips the codex block, restores or surgically strips `providers.ferry`, refuses an unprovable provider, and leaves `~/.codex` alone.
