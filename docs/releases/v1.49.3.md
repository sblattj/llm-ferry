# llm-ferry v1.49.3 — ferry update refreshes the client's goal skill

`ferry update` now refreshes the client's `using-the-goal-plugin` skill from the host share; an older host falls back to the old advice.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Fixed

- **A client reset re-fetches the goal skill.** In full OpenCode scope, `client-reset.sh` now downloads `/opencode/skills/using-the-goal-plugin/SKILL.md` from the host share, checks it is non-empty and named `using-the-goal-plugin`, and replaces `~/.config/opencode/skills/using-the-goal-plugin/SKILL.md`. Before, clients kept the text from their last bootstrap (v1.3.0, describing the removed `goal_pause` tool) after the plugin moved to 1.4.0. If the host share does not serve the file (an older host), the reset still succeeds and tells you once to re-run `client-bootstrap.sh`. Narrower scopes are unchanged.

## Tests

- `lib/ferry-clientbootstrap.test.py`: the stub host serves the skill; one test proves a reset replaces stale skill text byte-for-byte, another proves the 404 fallback leaves the file alone and the reset exits 0.
