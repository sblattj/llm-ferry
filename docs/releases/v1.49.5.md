# llm-ferry v1.49.5: goal plugin 1.4.1, a full context window no longer stops a goal

ferry now installs version 1.4.1 of the OpenCode goal plugin (`opencode-goal-pro-max-complete-plugin`). In 1.4.0 a goal could pause with "budget wrap-up requested" when peak context reached 80% of the model's window, even with token spend and time far below their limits. OpenCode compacts the session on its own when context fills, so 1.4.1 no longer treats context as a budget.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Changed

- **Goal plugin pinned to `v1.4.1`** (was `v1.4.0`). Context fullness no longer stops a goal or tells it to wrap up: the `context window reached` stop, the context branch of the 80% wrap-up and the context-remaining warnings are gone. Token spend (`maxTokens`) and the clock (`maxDurationMs`) keep their 80% wrap-up and hard stop, and a wrap-up now names which one triggered it (`token budget wrap-up requested` or `time budget wrap-up requested`). `/goal status` and the sidebar show current context, which drops on compaction, and say where the window size came from. The bundled `zod` goes from 4.4.3 to 4.6.7 (GHSA-mrhx-c7xc-m3w5). Plugin release notes: [v1.4.1](https://github.com/sblattj/opencode-goal-pro-max-complete-plugin/releases/tag/v1.4.1).
- The pinned spec changes, so OpenCode installs the new version fresh. The old 1.4.0 entry is still recognized by package name and replaced.
- The bundled `using-the-goal-plugin` skill is re-copied from the plugin's `v1.4.1` tag, in `opencode/skills/using-the-goal-plugin/SKILL.md` and in `client-bootstrap.sh`'s embedded copy.

## Tests

- `lib/ferry-integrate.test.py` and `lib/ferry-clientbootstrap.test.py` now expect the `v1.4.1` spec and version.
