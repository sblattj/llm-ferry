# llm-ferry v1.46.0 — goal plugin 1.2.0: a message steers a running goal

ferry now installs version 1.2.0 of the OpenCode goal plugin (`opencode-goal-pro-max-complete-plugin`). In 1.2.0, typing a message while a goal is running no longer pauses it. OpenCode answers the message, and the goal carries on with that message as its latest instruction.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Changed

- **Goal plugin pinned to `v1.2.0`** (was `v1.1.0`). The plugin's `noInterruptOnUserMessage` setting now defaults to `true`. Use `/goal pause` or `/goal stop` to halt a running goal. Set `noInterruptOnUserMessage: false` to get the old behavior, where a message paused the goal until `/goal resume`.
- **Bundled `using-the-goal-plugin` skill** updated to the copy at the plugin's `v1.2.0` tag, on the host and in `client-bootstrap.sh`.
- The pinned spec changes, so OpenCode installs the new version fresh. The old 1.1.0 entry is still recognized by package name and replaced.

## Fixed

- `docs/deep-dives.md` gave the plugin's OpenCode range as the pre-1.1.0 one. It now reads `engines.opencode ">=1.17.15 <3"`.

## Tests

- `lib/ferry-integrate.test.py` and `lib/ferry-clientbootstrap.test.py` now expect the `v1.2.0` spec. The existing check that `client-bootstrap.sh` writes a byte-identical copy of `opencode/skills/using-the-goal-plugin/SKILL.md` covers the new skill text.
