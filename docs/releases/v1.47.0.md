# llm-ferry v1.47.0 — the domestic fleet refuses Chinese models

`ferry up` and `ferry reload` now refuse to load a route config in which the `domestic` fleet can reach a Chinese model or provider. The domestic fleet has always been documented as US-only, but nothing enforced it. On one host, an agent re-pointed the domestic lanes at Kimi K3 and z.ai GLM after the ChatGPT subscription ran out for the week. Because domestic is the default fleet, every client ran on those providers for three weeks before anyone noticed.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Added

- **Domestic-fleet guard** (`front/ferry_fleet_guard.py`). It checks every `domestic.*` deployment, and every deployment the fleet reaches through `fallbacks`, `context_window_fallbacks`, `content_policy_fallbacks`, `default_fallbacks` or `model_group_alias`. The check matches the deployment's `model`, `api_base`, `custom_llm_provider` and `model_info.base_model` against a list of Chinese model and provider names, including Kimi/Moonshot, z.ai/GLM/Zhipu, DeepSeek, Qwen/DashScope, MiniMax, Baichuan, Yi, ERNIE, Doubao, Hunyuan and StepFun.
- On a violation, ferry prints each offending lane, how the domestic fleet reaches it, and the matching value, then exits 1. `ferry reload` checks before it stops anything, so a refused reload leaves the running proxy serving.
- If no Python with PyYAML is available to run the check, ferry refuses rather than skipping it.
- The `international` fleet is unaffected.

## Tests

- `lib/ferry-fleetguard.test.py`: 21 tests covering direct, OpenRouter-slug, fallback, alias and `default_fallbacks` violations. Also covered: US models that must not match, CLI exit codes, a clean pass on `litellm-route-example.yaml`, and a real `ferry reload` against a temp home. That reload refuses a violating config without calling any stop command, and a clean-config control does reach them.
