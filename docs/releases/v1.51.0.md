# llm-ferry v1.51.0: a host comes back by itself after a reboot

A reboot used to drop a host's share server and relay for good. `ferry up` brought back only the `8090` endpoint, so clients could not `ferry update` or `ferry expose-tmux` until someone restarted those by hand. Now the host restores itself at login, `ferry up` restores the whole host, and the failure is visible when it happens.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Added

- **`ferry autostart install|uninstall|status`** (macOS hosts) installs a LaunchAgent, `com.llm-ferry.host`, that runs `ferry boot` at login.
  - The plist carries a stable PATH, TMPDIR, and any `FERRY_SHARE_PORT` / `FERRY_RELAY_PORT` / `FERRY_LOCAL` / `FERRY_SHARE_RELAY` you exported.
  - It sets `AbandonProcessGroup`, so the services outlive the boot job.
  - Install is idempotent. It refuses on a client, or when the linked `ferry` is too old to have `boot`.
- **`ferry boot`** waits for the network, then runs `ferry up` if nothing listens on `8090` and checks `/health/liveliness`. It then makes sure the share server and relay are up.
  - It only starts what is missing.
  - On a client it does nothing.
  - Output goes to `~/.config/ferry/boot.log`.

## Changed

- **`ferry up`** (every mode except `--schematron`) also starts the share server and, on hosts that have run `ferry relay` once, the relay. Running listeners are left alone. `FERRY_SHARE_RELAY=0` skips this.
- **`ferry update --host`** (`host-reset.sh`):
  - It starts the relay when its port is free, and never restarts a running relay, which would drop published clients.
  - A relay that will not bind is a warning, not an abort.
  - It installs the login autostart even after a soft verify failure. `FERRY_AUTOSTART=0` skips the install.
- `FERRY_SHARE_PORT` and `FERRY_RELAY_PORT` override the `8095` / `8098` defaults.

## Fixed

- Fixes #5: the host share server and relay do not come back after a reboot, so clients cannot update or expose-tmux.
- `ferry update --client` exits non-zero when it cannot fetch or run `client-reset.sh`. Before, `curl | zsh` reported success on a dead host.
- `ferry status` shows the relay as OFFLINE when it is down. It no longer lists tmux clients from a stale `relay-published.json` as if they were connected.

## Tests

- New: `lib/ferry-autostart.test.py`, `lib/ferry-ensure-share-relay.test.py`, `lib/ferry-status.test.py`, and an unreachable-host case in `lib/ferry-update.test.py`.
- These use a sandbox HOME, a `launchctl` stub and spare ports, so nothing touches the real launchd or running services.
