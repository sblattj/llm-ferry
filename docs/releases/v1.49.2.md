# llm-ferry v1.49.2 — goal plugin 1.4.0: a goal stops only when you halt it

ferry now installs version 1.4.0 of the OpenCode goal plugin (`opencode-goal-pro-max-complete-plugin`). In 1.4.0 a running goal no longer stops on its own after a compaction, after a message you type, or after a recoverable error. It stops when you run `/goal halt`, when it completes, when a budget runs out, or when the model is truly blocked on input only you can give.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Changed

- **Goal plugin pinned to `v1.4.0`** (was `v1.3.0`). Compaction turns are no longer mistaken for a human interrupting, so they no longer pause the goal with "user intervention". A message you type steers the goal instead of pausing it. Aborted turns, provider errors, permission rejections, restarts, Plan-agent turns and the stall detectors record what happened and keep the goal going, with backoff. A failed continuation retries on its own after `promptRetryWakeMs` (default 5 s). There is a new `/goal halt`, and the model can no longer pause a goal (the `goal_pause` tool is gone). Plugin release notes: [v1.4.0](https://github.com/sblattj/opencode-goal-pro-max-complete-plugin/releases/tag/v1.4.0).
- The pinned spec changes, so OpenCode installs the new version fresh. The old 1.3.0 entry is still recognized by package name and replaced.
- The bundled `using-the-goal-plugin` skill is re-copied from the plugin's `v1.4.0` tag, in `opencode/skills/using-the-goal-plugin/SKILL.md` and in `client-bootstrap.sh`'s embedded copy. It now documents `/goal halt`, the new stop policy, and the warning against blocking.

## Tests

- `lib/ferry-integrate.test.py` and `lib/ferry-clientbootstrap.test.py` now expect the `v1.4.0` spec and version.
