# llm-ferry v1.42.4 — Codex subagents name their ferry lane, not GPT-6

When asked what model it runs on, a Codex session or subagent on ferry now names its llm-ferry lane (`heavy`, `medium`, `light` or `super-light`). It used to answer "GPT-6".

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Fixed

- **Codex catalog tiers no longer claim to be GPT-6.** `ferry codex` builds `~/.config/ferry/codex-catalog.json` by copying OpenAI's newest `gpt-*-astra/sol/luna` entries. Their prompt template says "You are Codex, an agent based on GPT-6". A `light` subagent was routed correctly to `international.flash` (GLM 5.3 Flash) but still repeated that line, so model selection looked broken. The catalog writer now rewrites the phrase to `an agent running on the llm-ferry "<tier>" lane` in every string of each copied entry. The upstream model behind a lane is still chosen by the front door at request time.

## Notes

- Pick it up by re-running `ferry codex` (or `ferry codex --wrappers`) on each machine to rewrite the catalog. Nothing changes on the host.
- Verified live: `codex-ferry exec` spawned a `light` subagent. ferry logged it on `international.flash`, and it answered `I am running on the llm-ferry "light" lane.` The same run with the old catalog answered "based on GPT-6".

## Tests

`lib/ferry-codex.test.py` (`CatalogTest.test_tiers_name_their_ferry_lane_not_the_copied_openai_model`): the identity phrase is rewritten in both `model_messages.instructions_template` and `base_instructions`, for both luna-derived tiers, and no "GPT-6" remains in the entry.
