# llm-ferry v1.30.2 — Client Cleanup Unwires the Goal Plugin Too

`client-cleanup.sh` now removes every goal-plugin entry `ferry opencode` wrote and the `/goal` command it merged in — from `opencode.json` **and** `tui.json` — instead of stripping only `provider.ferry`.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/v1.30.2/README.md)

## What v1.30.1's cleanup left behind

v1.30.1 taught `ferry opencode` to write the goal plugin in three places: the `plugin` array of `~/.config/opencode/opencode.json`, a top-level `command.goal`, and — new in that release — the same spec mirrored into `~/.config/opencode/tui.json`, because OpenCode reads TUI-half plugins from `tui.json` alone.

`client-cleanup.sh` was never taught the other two thirds. Its section 4 stripped `provider.ferry` (and a dangling `model`/`small_model`) and stopped. A "cleaned" client therefore kept:

- `"plugin": ["opencode-goal-plugin@https://github.com/sblattj/OpenCode-goal-plugin/archive/refs/tags/v0.10.1.tar.gz"]` in `opencode.json`,
- `command.goal` — so `/goal` stayed in the slash-command menu with no plugin behind it,
- an entire `~/.config/opencode/tui.json` that existed for no reason but ferry.

The next bare `opencode` still fetched and loaded ferry's plugin on a machine whose owner had just uninstalled ferry.

## What changed

- **Both files, one code path.** A single `unwire_goal_plugin <file> <opencode|tui>` function does the removal, so sections 4 and 4b cannot drift apart. Everything else in either file is left exactly as it was, and the original is snapshotted to `<name>.<UTC>.jsonc` before the first write — one snapshot per file per run, the same convention `ferry opencode` uses.
- **Every spelling ferry ever wrote.** The matcher mirrors `is_goal_spec()`/`is_path_entry()` from `lib/ferry-integrate.zsh`: the bare npm name, `@prevalentware/opencode-goal-plugin`, `willytop8/…`, `github:owner/repo` with or without a `#ref`, `git+https://…`, `archive/refs/tags/*.tar.gz` URLs plain or `name@`-prefixed, and the `["spec", {opts}]` tuple form. A new suite case asserts the two copies of the list stay in sync.
- **A local fork is never removed.** OpenCode accepts a filesystem path as a plugin entry, and Bun cannot resolve a private repo over `github:`, so a hard fork of the plugin can only be named by path. `/…`, `./…`, `~/…` and `file://…` entries are yours, not ferry's, and a config holding only one is left byte-identical — no snapshot, no rewrite.
- **`command.goal` goes only when it is verbatim.** `ferry opencode` merges the command in and never overwrites an existing one, so anything that does not deep-equal ferry's version is the user's own command wearing our key, and it stays.
- **Emptied keys are dropped, not left as litter.** `plugin` disappears when the last entry was ours; `command` disappears when `goal` was the only one.
- **`tui.json` is deleted when it held nothing else.** If what remains is only `$schema` (which ferry wrote when it created the file) and an emptied `plugin`, the file itself is the trace and it goes — no snapshot, because nothing in it was not ours. A `tui.json` carrying a theme or any other key is rewritten with a snapshot beside it instead.
- **`--dry-run` reports all of it and writes nothing.** The dry-run grep now also finds a goal-plugin entry and a `"goal": {` block, and it deliberately does not report a local-path fork.
- **Running cleanup twice is a no-op.** The second pass finds nothing, prints `Nothing ferry-shaped found — file left unchanged.`, and takes no snapshot.
- **The package cache is still OpenCode's.** `~/.cache/opencode/packages` is left alone: `ferry opencode` purges the directories it orphans, but an uninstall does not get to empty a cache that belongs to the `opencode` binary this script deliberately keeps.

`lib/ferry-clientbootstrap.test.py` grew a `ClientCleanupGoalPluginTest` class covering each of these against a throwaway `$HOME`, including the end-to-end `client-bootstrap.sh` → `client-cleanup.sh` round trip.

## Update instructions

### 1. Update the host first

From your host `llm-ferry` repository:

```bash
git pull --ff-only
ferry update --host
```

### 2. Update each client

On each client laptop:

```bash
ferry update --client
```

`client-cleanup.sh` is fetched fresh from the host's share server on every run, so a client that is only ever *cleaned* needs nothing more than an up-to-date host.

### 3. Verify

On a machine you actually want to unwire, run the dry pass first:

```bash
curl -fsSL http://your-mac.local:8095/client-cleanup.sh | zsh -s -- --dry-run
```

Expect `would remove the goal plugin entry from …/opencode.json`, `would remove the /goal command from …`, and `would remove the goal plugin entry from …/tui.json`. After the real run:

```bash
grep -c goal-plugin ~/.config/opencode/opencode.json   # 0
ls ~/.config/opencode/tui.json                         # No such file or directory
```
