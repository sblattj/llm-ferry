# llm-ferry v1.44.0 — tmux into a client without Remote Login

`ferry expose-tmux` no longer needs Remote Login, which takes admin rights to turn on. When nothing answers on the client's port 22, ferry runs its own sshd as the ordinary user, with no sudo, and publishes that instead. The host's `ferry tmux` works the same as before.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Added

- **A no-sudo sshd for `ferry expose-tmux` (client).** With no flag, ferry checks 127.0.0.1:22 for an `SSH-` banner. If one answers, ferry uses the system sshd as before. If not, it starts `/usr/sbin/sshd -D` as you, on a free 127.0.0.1 port, and publishes that port through the relay on host port **8101**. The sshd stops when `expose-tmux` stops, whether by Ctrl-C or `kill`. New flags:
  - `--user-sshd` always runs ferry's own sshd.
  - `--system-sshd` requires the sshd on port 22.
- **A dedicated host key for tmux.** `ferry relay` creates `~/.config/ferry/tmux_ed25519` once. A client's no-sudo sshd trusts only that key, which it fetches from the relay with the relay token (a new `hostkey` request). `ferry tmux` offers the key with `-i` whenever it exists.

## Notes

- The no-sudo sshd listens on 127.0.0.1 only. It accepts only public keys, and only the host's ferry key. Password login, forwarding and tunnels are off. Its state lives in `~/.config/ferry/tmux-sshd/`. The host key there is made once, so the host's `known_hosts` entry stays valid across runs.
- A client on the no-sudo sshd registers with `sshd: "user"`. `ferry tmux` saves its host key under `ferry-tmux-<label>-user`, so switching a laptop between the two sshds doesn't trip ssh's "REMOTE HOST IDENTIFICATION HAS CHANGED" warning.
- **Upgrade the host first.** Run `ferry update` on the host and restart the relay (`ferry down`, then `ferry relay`). A relay started before this release doesn't answer the `hostkey` request. A client that asks it is told to upgrade the host.
- A client using `--local PORT` or the system sshd behaves exactly as in v1.43.

## Tests

- `lib/ferry-relay.test.py` (`ExposeTmuxUserSshdTest`): an end-to-end run with a real relay, a real no-sudo sshd and real ssh. The host key logs in, a freshly generated other key is refused, and `authorized_keys` holds exactly the host's key. After SIGTERM and after SIGINT the sshd is gone, and after SIGTERM the relay drops the port. Also covered: the `hostkey` request with a right and a wrong token, the relay creating the key at 0600, `sshd: "user"` being stored, and the messages for an older relay and a wrong token.
- `lib/ferry-tmux.test.py`: `-i <key>` appears only when the key exists, and a user-sshd client gets the `-user` host-key alias.
