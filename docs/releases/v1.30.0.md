# llm-ferry v1.30.0 — `light` and `standard` Workers Replace `general`

`ferry opencode` now disables OpenCode's built-in `general` subagent and writes two custom subagents in its place, pinned by complexity band: `light` (tasks rated 0-50 of 100) on `flash`, and `standard` (51-100) on `medium` when the host advertises it. The driver picks the worker; the lane behind each name stays the host's business.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/v1.30.0/README.md)

## What changed

- **The finding:** OpenCode's task tool has no model parameter. The driver only picks an agent *name*, and each agent is pinned to one lane in the config. Since v1.29.1 `general` was pinned to `medium`, so every `general` dispatch ran on the medium lane, including a 15/100 read-only lookup that only needed `flash`. The task tool shows the driver each subagent's `description` at dispatch time, so the complexity rule belongs in the description, and the split belongs in the agent table.
- **Two workers, one rule:**
  - `light` — "Worker for tasks rated 0-50 of 100 complexity: exploration follow-ups, small fixes, easy implementation, mechanical edits with clear instructions. Full tool access. Default worker; use standard only when the task clearly needs deeper judgment." Cloud lane `flash`.
  - `standard` — "Worker for tasks rated 51-100 of 100 complexity: multi-file implementation, ambiguous debugging, design judgment. Full tool access. Use light for anything rated 50 or below." Cloud lane `medium` when advertised, otherwise `flash`.
  - Both are written as `mode: "subagent"` with full tool access, exactly what `general` had. `explore` stays read-only on `flash`.
- **`general` is disabled, not deleted:** the takeover writes `"general": {"disable": true}`. A deleted key would let OpenCode's built-in `general` reappear with the driver's expensive model.
- **Profiles remap both workers together:** `--small-model <lane>` overrides `light`, `standard` and `explore`; `--super` sends all three to `super-flash`; `--local` sends all three to `local-sub`. An older host whose catalogue lacks `medium` gets both workers on `flash`.
- **Local fan-out recipe:** `/fan-out` and the `spawning-subagents` skill now dispatch `subagent_type: "light"` (the copies in `client-bootstrap.sh` are kept in sync).
- **Docs and example config** describe the new agent table.

## Update instructions

### 1. Update the host first

From your host `llm-ferry` repository:

```bash
git pull --ff-only
ferry update --host
```

This rebuilds the global `ferry` binary, relinks it, and rewrites the local OpenCode profiles (`~/.config/ferry/opencode-*.json` and the default `opencode.json`) with the new agent table.

### 2. Update each client

On each client laptop:

```bash
ferry update --client
```

### 3. Verify with the real loader

```bash
opencode agent list --pure | grep -E '^(light|standard|general) '
opencode debug agent standard --pure | grep -E '"modelID"|"description"'
```

`general` must be absent, `light` and `standard` must be listed as subagents, and `standard` must resolve to `ferry/medium` on a host that advertises it.

### 4. If something else manages your `opencode.json`

Any other tool that rewrites the `agent` block (a dotfiles renderer, for example) must write the same table, or the two writers will keep reverting each other's pins. The exact entries are in `client-config-example.json`.
