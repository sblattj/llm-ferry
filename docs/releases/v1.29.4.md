# llm-ferry v1.29.4 — Pinned OpenCode Goal Plugin Ref and the `/goal` Command

Pins the OpenCode goal plugin entry ferry writes to a git ref — `github:sblattj/OpenCode-goal-plugin#v0.9.1` — so a new plugin version actually reaches machines that already have one installed, and wires the plugin's `/goal` slash command into the generated config.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/v1.29.4/README.md)

## What changed

- **The cache-freeze finding:** OpenCode installs a plugin into `~/.cache/opencode/packages/<the spec string>/` and, if `node_modules/<pkg>` already exists in that directory, returns immediately without refetching. An *unpinned* `github:` spec is therefore frozen forever at whatever commit the machine first fetched — hosts were still running goal plugin 0.9.0 while the fork's HEAD was 0.9.1, and no `ferry update` could move them. The spec string is the cache key, so a **new** string means a new cache directory and a guaranteed fresh install.
- **Pinned entry:** `ferry opencode` now writes `github:sblattj/OpenCode-goal-plugin#v0.9.1`. Cutting a plugin release means bumping `GOAL_PLUGIN_REF` in `lib/ferry-integrate.zsh`; that bump is what rolls the new version out.
- **Automatic re-pinning:** an existing entry that is unpinned, or pinned to a different ref, in either the plain-string or the `["pkg", {opts}]` tuple form, is rewritten to the current pin on every run (tuple options are preserved). Ferry owns this entry; a differing ref is drift.
- **Local forks unchanged:** a filesystem path to your own fork of the plugin still counts as present and is never replaced.
- **`/goal` slash command:** the plugin's command only appears if the config carries a top-level `command.goal` entry, and none of the generated configs had one. Ferry now *merges* one in (description / `$ARGUMENTS` template / `build` agent) when it is absent, leaving a `goal` entry you customised — and every other command — byte-for-byte alone. This is OpenCode's `command` config key, distinct from the `~/.config/opencode/command/*.md` files ferry installs for `/fan-out`.

## Update instructions

### 1. Update the host first

From your host `llm-ferry` repository:

```bash
git pull --ff-only
ferry update --host
```

This rebuilds the global `ferry` binary, relinks it, and updates local OpenCode profiles (`~/.config/ferry/opencode-*.json` and default `opencode.json`).

### 2. Update each client

On each client laptop:

```bash
ferry update --client
```

Clients fetch the updated `ferry` binary from the host and regenerate their local OpenCode profiles, re-pinning the goal plugin automatically.

### 3. Launch opencode once

Rewriting the config does not install anything by itself — **opencode must be launched once** for it to fetch the newly-specified plugin into its package cache. After that launch, verify the installed version:

```bash
grep -A1 '"node_modules/opencode-goal-plugin"' ~/.cache/opencode/packages/github:sblattj/opencode-goal-plugin*/package-lock.json
```

The resolved entry should name the `v0.9.1` ref. `/goal` should also now be listed in opencode's slash-command menu.
