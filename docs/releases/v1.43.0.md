# llm-ferry v1.43.0 — the host can tmux into a client

The host can now open a tmux session on a client laptop, and the client still only makes outbound connections. The client publishes its own sshd through the reverse relay, and the host runs ssh through the relay and attaches tmux.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Added

- **`ferry expose-tmux` (client).** Checks that `tmux` is installed and that 127.0.0.1:22 answers with an `SSH-` banner. If nothing is listening there, it tells you to turn on Remote Login. It then publishes sshd through the relay, by default on host port **8101**, tagged `kind: "tmux"`. The registration now also carries the client's login name.
- **`ferry tmux [CLIENT]` (host).** Picks a published client by label or port. With exactly one published client, it picks that one. It then runs `ssh -t` into it and attaches `tmux new-session -A -s ferry`. Options:
  - `--list` shows the clients that published.
  - `--session NAME` and `--user U` override the session name and the login name.
  - `--print` shows the ssh command without running it.
- **`ferry status`** shows a `ferry tmux <label>` hint for each published tmux client.

## Notes

- ssh is what authenticates and encrypts the session. The relay token only proves who published. The client needs Remote Login on and must accept your key or password.
- Each client's host key is saved under its own name (`HostKeyAlias=ferry-tmux-<label>`), so a client that later reuses the same port doesn't trigger a known_hosts mismatch. The remote command puts `/opt/homebrew/bin` on `PATH`, because a non-interactive macOS ssh session doesn't include Homebrew.
- Login and session names are checked against `[A-Za-z0-9._-]`, and a login name starting with `-` is refused, so neither can be read as an ssh option.
- Run `ferry update` on the host and on each client that will publish. A relay that is already running keeps the old code until it's restarted, and the old code doesn't store the login name. Until then, `ferry tmux` needs `--user`.
- Verified end to end: a user-level sshd on a high port, a real relay, `expose-tmux`, and then `ferry tmux` over real ssh. On the client, `tmux ls` showed `ferry: 1 windows … (attached)`. Before the attach there was no tmux server.

## Tests

- `lib/ferry-tmux.test.py` (new, 23 tests): choosing a client, `--list`, `--print` argv, bind addresses, ambiguous and unknown clients, rejected names, the client-mode guard, and the `ferry status` hint.
- `lib/ferry-relay.test.py` (`ExposeTmuxTest`): the SSH-banner preflight, a missing `tmux`, a closed port, publishing with `kind: "tmux"` plus the login name, and a hostile login name not being stored.
