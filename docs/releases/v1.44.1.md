# llm-ferry v1.44.1 — `ferry status` names whatever is really on a port

`ferry status` used to say a service was ONLINE whenever any process listened on its port. On the host this release was written on, it reported "Reverse relay is ONLINE" while port 8098 was held by an orphaned test proxy from a deleted worktree, and no relay was running at all. It also reported "VNC viewer is ONLINE" for a stray `python -m http.server` on 8099.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Fixed

- **`ferry status`** reports the HF pass-through proxy, the HTTP download proxy, the reverse relay and the VNC viewer as ONLINE only when the process holding the port is ferry's own. Each ferry service carries a marker in its command line, and status checks for it. When another process holds the port, status prints that process's PID and command, and which ferry command can't start until the port is freed.
- **`ferry relay`** no longer says "a relay may already be running" when the port belongs to something else. It names the process holding the port.

## Tests

- `lib/ferry-serve.test.py` (`TestPortHolder`): checks a free port, a port held by a process carrying the marker, and a port held by one without it.
- `lib/ferry-vnc.test.py`: the status tests now start a listener that carries `ferry-vnc-marker`. They skip, and name the process, when a non-ferry process already holds port 8099.
