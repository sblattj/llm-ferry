# llm-ferry v1.42.0 — local GPU lanes are opt-in

The three local MLX GPU lanes (`local-orch`, `local-sub`, `local-schematron`, ~42 GB of weights) no longer start, and their models no longer download, unless the operator explicitly asks. A plain `ferry up` now serves the cloud lanes only.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## What's new

```bash
ferry up                    # cloud lanes only; a banner says the local GPU lanes are off
ferry up --with-local       # the full stack: cloud + the three MLX lanes (same as -a / --all / --stack)
FERRY_LOCAL=1 ferry up      # persistent opt-in: a no-arg `ferry up` launches the full stack
ferry install --with-local  # also download the local models (macOS)
```

- **`ferry up` (no args) = cloud lanes.** Same as `--route`: no `mlx_vlm.server` requirement, no MLX launch, no 900 s readiness waits. The banner names the three lanes that are off and how to opt in.
- **Opt-in surface.** `--with-local`, `-a`, `--all`, `--stack` (full stack); `FERRY_LOCAL=1` in the shell or in `~/.config/ferry/secrets.env` (ferry already sources that file at startup, like `GEMINI_API_KEY`) makes the no-arg default the full stack. Only the literal `1` counts; unset, empty, `0` or anything else is off. The single-lane flags (`-l/--local`, `-s/--sub`, `--local-orch`, `--local-sub`, `--local-schematron`, `-o/--orch`) and `--schematron` are explicit requests and are unchanged.
- **`ferry up -i` falls back to the cloud lanes**, never a local lane: a missing `GEMINI_API_KEY`, a failed catalog fetch and an unparseable list all serve `--route`. The menu's default (Enter, no tty, bad number) is now a new first entry, "CLOUD LANES"; the full stack and the single GPU lanes remain as explicit entries.
- **`ferry install`** skips the model downloads and the nemotron batching patch on macOS unless `--with-local` or `FERRY_LOCAL=1`, and prints how to fetch them. `mlx-vlm` itself (a small tool install) is still installed, so opting in later needs no reinstall. `host-bootstrap.sh` takes the same `--with-local` / `FERRY_LOCAL=1` switch.
- **`host-reset.sh --full`** relaunches the local lanes only if `FERRY_LOCAL=1` (shell or `secrets.env`, file wins as in ferry) or an MLX port was listening when the reset began; otherwise it is a clean cloud-only `ferry down && ferry up --route`. The verifier reports a closed MLX port as "off (opt-in)" instead of "DOWN" when the lanes are not wanted.

- **Prime Agent verified end to end.** v1.41.0 shipped `ferry prime` checked against prime-agent's source only. It now has been run against a live prime-agent 0.9.8: a plain prompt, a tool-using task and two lanes (`heavy`, `flash`) all went through the front door with 200s. The "not yet tested" caveats are gone from the README, the example config and the deep dive. Whether a running daemon re-reads `models.json` without a restart is still unknown.

## How it works

- `_ferry_local_enabled` (`lib/ferry-serve.zsh`) is the single predicate. `cmd_up` starts at `LAUNCH_MODE="route"` and moves to `stack` only when it is true or a stack flag is parsed.
- The decision in `host-reset.sh` is made before `ferry down`, while the ports can still be probed.

## Notes

- Existing hosts that relied on a no-arg `ferry up` for the full stack must add `FERRY_LOCAL=1` to `~/.config/ferry/secrets.env` (or use `ferry up --with-local`). Clients are unaffected: lane names are unchanged, and `local-*` lanes are still listed by `/v1/models` but have no backend unless started.
- `ferry reload` and `host-reset.sh` without `--full` never touched the GPU lanes and still do not.
- `ferry install` now accepts one flag, so it is no longer in the no-argument command set.

## Tests

`lib/ferry-serve.test.py` gains `TestLocalLanesAreOptIn`: the real `_ferry_local_enabled` predicate (only `1` enables), the no-arg default is not the stack, `--with-local`/`-a`/`--stack` select it, single-lane flags stay explicit, the route branch launches no MLX, `-i` fallbacks and default choice are cloud-only, and `install` skips downloads and the patch by default. `lib/ferry-hostreset.test.py` covers the `--full` decision (opt-in or running, decided before `down`), the real `local_opted_in` / `local_lanes_running` helpers, and the verifier's "off" versus "DOWN" wording. `lib/ferry-main.test.py` drops `install` from the no-argument set.
