# llm-ferry v1.50.0: goal plugin 1.5.1, cloud lanes compact at 200k

A long OpenCode session on a ferry cloud lane used to grow without limit, because a model with no configured limit resolves to `limit.context: 0` and OpenCode never auto-compacts those. Generated configs now give the cloud lanes a limit, and the pinned goal plugin forces a compaction on its own.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Changed

- **Cloud lanes carry a compaction limit.** `heavy`, `flash`, `super-flash` and `medium` get `limit: {context: 208000, input: 208000, output: 0}`. The lanes really have ~1M windows, so this is a policy number, not capacity. `output: 0` is there because OpenCode rejects a limit without `output`, and 0 is what it already resolves to, so the output cap does not change. Local lanes keep their 131072/8192.
- **Where the compaction lands.** With `compaction.reserved: 8000` in your OpenCode config, the host compacts at 200k. Ferry does not write that key, so without it the host uses its default reserve and compacts earlier, at about 188k.
- **Goal plugin pinned to v1.5.1.** Goal sessions force a compaction at 200,000 tokens by default (`--compact-at <n>`, `0` turns it off), and the goal keeps working. The bundled `using-the-goal-plugin` skill is updated to match.

## Tests

- `lib/ferry-integrate.test.py` gains `test_cloud_lanes_carry_the_200k_compaction_limit`, covering the four cloud lanes and the `--local` pair.
