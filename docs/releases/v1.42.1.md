# llm-ferry v1.42.1 — `light` / `super-light` subagents in Prime Agent

Prime Agent can now spawn a subagent on the `light` and `super-light` tiers, the same tier names Codex uses.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## What's new

```bash
ferry prime                                   # re-run to pick up the aliases
prime-agent --provider ferry --model heavy    # then: "spawn a subagent using model light …"
```

- **`ferry prime` lists the tier aliases.** The front door has accepted `light` / `super-light` as names for `flash` / `super-flash` since v1.41.0, but `/v1/models` does not list aliases, and prime-agent only spawns a child (`rlm.spawn(..., model=...)`) on a model in its provider's list. Without the alias it fell back to the parent's model. `ferry prime` now appends `light` when `flash` is served and `super-light` when `super-flash` is, and `--model light` is accepted as the default lane.

## Notes

- Existing installs: re-run `ferry prime` (it snapshots `models.json` first), then restart prime-agent.
- Ask for the model explicitly ("using model light"). A bare "spawn a subagent light" reads as a subagent *named* light, which inherits the parent's model.
- Verified live with prime-agent 0.9.8 in a real repo: a `heavy` parent spawned a child on `ferry/light` and got its `PONG` reply in 2 of 3 runs. In the other run the `light` child printed its `agent_message.send(...)` call as text instead of executing it. `light`, `flash` and `super-light` each completed a Python tool task as the parent model, so treat that as occasional model behavior, not wiring.

## Tests

`lib/ferry-prime.test.py`: an alias is listed only when its target lane is served, the fixed fallback set carries both aliases, and `--model light` is a valid default. The missing-binary test no longer depends on whether prime-agent is installed on the test machine (it shipped in v1.42.0).
