# llm-ferry v1.45.1 — `ferry tmux` finds a per-user Homebrew tmux

`ferry tmux` connected to a managed Mac and then failed with `zsh:1: command not found: tmux`. That Mac's Homebrew lives in the user's home (`~/homebrew`) because the account has no admin rights, and the remote command only looked in `/opt/homebrew/bin` and `/usr/local/bin`. In the same session, an unquoted `--dir ~/dev` reached ferry already expanded to the host's home, a path that does not exist on the client.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Fixed

- **`ferry tmux`** searches the usual tmux locations on the client before starting tmux. In order: `$HOME/homebrew/bin`, `$HOME/.homebrew/bin`, `$HOME/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, `/opt/local/bin` (MacPorts), `$HOME/.nix-profile/bin` and `/run/current-system/sw/bin`. When tmux is in none of them, the client prints `ferry: tmux is not installed on this client` and the session exits 127.
- **`ferry tmux --dir`** maps a path under the host's home back to `~/...` on the client when the client login differs from the host's. This happens when your shell expands an unquoted `~` before ferry sees it. ferry prints a note on stderr when it does this. Quoting the path (`--dir '~/dev'`) skips the note.

## Tests

- `lib/ferry-tmux.test.py` (`TmuxRemotePathTest`): runs the generated remote command in a real `sh` with a fake client `$HOME`. It checks that a tmux in `~/homebrew/bin` is found, and that a missing tmux gives the message and exit code 127.
- `lib/ferry-tmux.test.py` (`TmuxDirTest`): checks that a path under the host's home is mapped to `~`, and that it is left alone when the client login is the host's own.
