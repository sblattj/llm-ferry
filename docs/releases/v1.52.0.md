# llm-ferry v1.52.0: every popular agentic coding CLI runs on ferry

Until now ferry wired opencode, Claude Code, Codex, Cline and Prime Agent, and `ferry pi`, `ferry gemini` or `ferry aider` printed "Unknown command". This release adds fourteen more coding CLIs, each with a `ferry <client>` command that writes a `<client>-ferry` wrapper on your lanes and leaves the plain command and your own config alone.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md#agentic-coding-clis)

## Added

- **`ferry <client>`** for Pi (`pi`), oh-my-pi (`omp`), Gemini CLI (`gemini`), Qwen Code (`qwen`), OpenHands (`openhands`), Open Interpreter (`interpreter`), Goose (`goose`), Aider (`aider`), Codewhale (`codewhale`), Reasonix (`reasonix`), Crush (`crush`), Kilo Code (`kilo`), Kimi Code CLI (`kimi`) and GitHub Copilot CLI (`copilot`).
  - Each one points the client at `http://HOST:8090/v1` with this machine's device key (or the master key) and the `X-Ferry-Client` / `X-Ferry-Fleet` headers, on `heavy` unless you pass `--model <lane>`.
  - Common flags: `--host --port --key --model --keep`, and `--unwire [--dry-run]` to undo.
  - The key lives in `~/.config/ferry/agents.key` (0600) and the wrappers read it at run time. It is never in argv or in a client's config.
  - `~/.config/ferry/<client>.json` records what was written. `--unwire` removes only that, and keeps a file you changed since.
  - Each client was run end to end, real binary through its wrapper, against a stub endpoint in a throwaway `$HOME`.
- **`ferry agents [--list|--installed]`** lists the clients ferry can wire and which are installed.
- **Bootstrap, reset and cleanup.** `client-bootstrap.sh` wires every listed client that is already installed and records `<client>_mode` in `client.json`. `--with-<client>` wires one that is not installed yet, `--no-<client>` skips one, `--no-agents` skips them all. `client-reset.sh` re-applies the clients whose mode is `full`, and `client-cleanup.sh` unwires them all.
- **Device keys on the Gemini-native routes.** `POST /v1beta/models/<lane>:generateContent` and `:streamGenerateContent` now take a device key, with the same lane limit, RPM, monthly token budget and metering as `/v1/chat/completions`. So `gemini-ferry` works on a client laptop.

## Changed

- Unlike Cline and Codex, which the bootstrap wires before they are installed, the new clients are wired only when their binary is on `PATH` at bootstrap time.

## Fixed

- Fixes #3: popular agentic coding CLIs had no `ferry <client>` command and could not be pointed at ferry.
- `ferry cline` with `CLINE_DATA_DIR` set wrote to `$CLINE_DATA_DIR/data/`, one level deeper than the Cline CLI reads. It now treats `CLINE_DATA_DIR` as the data directory itself and `CLINE_DIR` as the root, the same way the CLI does. `client-cleanup.sh` looks in the same place.

- A Gemini-native stream (`:streamGenerateContent`) served by litellm's completion adapter, which handles every non-Gemini lane, reported no usage, so the front door metered it as 0 tokens. The front now asks the adapter for stream usage and charges it.

## Notes

- Open Interpreter means the current Rust `interpreter` (0.0.x). The legacy Python 0.4 package is not wired.
- The Python `kimi-cli` is archived, so `ferry kimi` wires the npm Kimi Code CLI (`@moonshot-ai/kimi-code`).
- Gemini CLI rewrites the model names `auto`, `pro`, `flash` and `flash-lite`, so those ferry lane names cannot be picked under `gemini-ferry`. The other lanes work.
- Reasonix has been unmaintained upstream since 2026-11-12.
- On a non-Gemini lane, a streamed Gemini-native reply carries no `usageMetadata` to the client (litellm's adapter leaves it off the wire), so Gemini CLI's own token stats read 0 there. ferry still counts those tokens: the front door reads them off the adapter, so a device key's budget and the `ferry keys list` token count are right. Non-streamed replies carry `usageMetadata` as before.
