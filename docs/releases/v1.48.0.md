# llm-ferry v1.48.0 — clients are locked to the domestic fleet

v1.47.0 made `ferry up` and `ferry reload` refuse a route config whose `domestic` fleet reaches a Chinese model. This release closes the gaps around that check. Only the host may use a non-domestic fleet; every client is locked to `domestic`. The front door enforces the guard itself, at startup and on every request, so a deployment swapped or added at runtime cannot slip past it.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Added

- **Client lock.** A non-host caller that asks for another fleet gets HTTP 403: `this ferry host locks clients to the domestic fleet; 'international' is host-only`. That covers a fleet-qualified model name (`international.heavy`), an `X-Ferry-Fleet` header, and a sticky selection through `ferry fleet use` (`POST /v1/ferry/fleet`). A client's bare lanes always resolve to `domestic`, even when the host-wide default or a stored client selection names another fleet.
- **Strict host test.** The host is a loopback caller with no device key, no `X-Forwarded-For`, `Forwarded`, `X-Real-IP` or `Tailscale-*` header, and an `X-Ferry-Client` that is absent or `host`. A client proxied through `tailscale serve` now counts as a client. Before, it resolved as the host.
- **Startup check.** The front door runs the domestic-fleet guard when it starts and refuses to start on a violation, whoever launched it.
- **Per-request check.** A litellm pre-call deployment hook refuses (403) any request for a `domestic.*` lane, and any request from a client, that would be served by a Chinese deployment. This also catches deployments swapped or added at runtime. A mixed lane retries onto a US deployment. Requests from the front door's clients carry a `ferry_domestic_only` metadata marker so the hook sees them through any lane name.
- **`ferry status` warning.** If something other than ferry's front door holds the front-door port (for example a bare `litellm`), `ferry status` warns that the guard and the client lock are not active.
- On a client, `ferry fleet use international` prints the server's 403 message with a hint and exits 1. `ferry fleet ls` marks non-domestic fleets `(host only)`.

## Changed

- README and `docs/deep-dives.md` describe the lock and the strict host definition. The old note that a headerless `tailscale serve` client resolves as the host is gone.

## Tests

- `lib/ferry-clientlock.test.py` (29 tests): all three refusal paths, bare-lane resolution under an international default or selection, proxied-loopback and device-key callers counted as clients, and the metadata marker.
- `lib/ferry-fleetpolicy-front.test.py` (20 tests): startup refusal and acceptance, and the hook run against a real litellm `Router` with mock deployments. A domestic or marked request never returns the Chinese deployment's response; an unrestricted one does.
- `lib/ferry-fleet.test.py` and `lib/ferry-serve.test.py`: the client 403 message, `(host only)`, and the status warning with a ferry-front control.
- Existing front-door tests that used a LAN peer as a generic caller now run as the host.
