# llm-ferry v1.42.3 — Codex runs on the z.ai lanes again

Codex requests to the `light` and `medium` lanes are served by their z.ai primaries again, instead of failing over to OpenRouter on every call.

[Read the project overview](https://github.com/sblattj/llm-ferry/blob/main/README.md)

## Fixed

- **z.ai deployments no longer reject Codex requests.** Codex CLI sends a `tool_search` tool with every Responses request, and z.ai answers `400 ZaiException - tools[N].type:type is illegal`. The router then fell back to OpenRouter for every Codex call on `international.flash` (`light`) and `international.medium` (`medium`). The front door now registers a LiteLLM deployment-level hook that drops `tool_search` tools only when the chosen deployment is a z.ai one. OpenRouter and ChatGPT hops still receive the tool, and the caller's request is copied rather than edited, so a fallback hop sees the original list.

## Notes

- Pick it up on a host with `ferry reload`. Clients need nothing.
- Verified live with a captured Codex request: before, `light` and `medium` with fallbacks disabled returned the 400. After, both returned 200 from their z.ai primaries, with or without fallbacks enabled. A `heavy` Codex parent spawning a `light` subagent got its reply in 27 s.

## Tests

`lib/ferry-front.test.py` (`TestZaiToolSearchStrip`, 7 tests): `tool_search` removed for z.ai deployments (by `zai/` model prefix or `custom_llm_provider`), other tools kept, the original list not mutated, non-z.ai deployments untouched, malformed input left alone, and the install idempotent.
